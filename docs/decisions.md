# Design Decisions / 決策紀錄

A running log of the "why" behind project decisions, so future maintainers
don't have to re-litigate them. New entries: one line for the decision, one
for the reason, one for what it cost. / 記錄每個關鍵決定背後的原因，避免日後重蹈覆轍。新增條目：決定一行、原因一行、代價一行。

| ID | Date / 日期 | Decision / 決定 | Why / 原因 | Cost / 代價 |
| --- | --- | --- | --- | --- |
| D1 | 2026-07 | Desktop (PySide6) is the default entry; NiceGUI web is opt-in (`--web` or the menu switch) / 桌面版為預設入口，Web 選用啟動 | The web server should never run silently in the background; desktop gives the better default UX / Web 不該默默佔用資源，桌面版體驗較佳 | Two entry points; desktop and web sessions are separate / 兩套入口、session 各自獨立 |
| D2 | 2026-07 | Split the codebase: `game.py` / `ai.py` / `SBA.py` / `webui.py` / `qtui.py` / 拆分模組 | Pure logic separated from both UIs so engines stay reusable and testable / 邏輯與 UI 分離，引擎可重用、可測試 | None / 無 |
| D3 | 2026-07 | Solver is removed from the AI menus (engine kept for the analysis panel) / Solver 移出選單，保留給分析面板 | It is a tablebase oracle, not a meaningful opponent / 它是殘局表神諭，不是有意義的對手 | Menu shows one less AI / 選單少一個選項 |
| D4 | 2026-07 | AlphaZero trains/evaluates on Ultimate only / AlphaZero 僅限終極模式 | Normal Tic Tac Toe is a solved game; training on it is meaningless / 普通井字棋已被破解，訓練無意義 | Normal has no neural option / 普通模式無神經網路選項 |
| D5 | 2026-08 | PyQt-SiliconUI (PySide6 fork) is vendored under `vendor/siui/` and the project was relicensed to GPLv3 / 隨附 SiliconUI 並改為 GPLv3 | The desktop bundles GPLv3 code, so the combined work must be GPLv3; pip cannot install the PySide6 branch (no `setup.py`) / 合併作品須為 GPLv3；PySide6 分支無 setup.py 無法 pip 安裝 | Whole project is now GPLv3 (was MIT) / 全專案授權由 MIT 改為 GPLv3 |
| D6 | 2026-08 | Won chunks fill with the player's color; hovering reveals the cells again / 勝者區塊填色，hover 顯示回小格 | Bigger, clearer win label that stays inspectable / 勝者標示更清楚且仍可檢視 | Hover state + fade animation added to the board / 棋盤多一個 hover 狀態 |
| D7 | 2026-08 | Fonts prefer Noto Sans TC / 字型優先 Noto Sans TC | 微软雅黑 is not installed on every Windows system and broke text rendering / 雅黑非每台 Windows 都有，會造成文字破圖 | None / 無 |
| D8 | 2026-08 | Added `MCTS+GRAVE`; `MCTS+RAVE` is hidden from the menus / 新增 GRAVE，RAVE 移出選單 | GRAVE (Cazenave 2015) is RAVE's successor: same bias, lower memory; a 30-game bench put it ahead of both MCTS and RAVE / GRAVE 是 RAVE 的後繼者，30 局對戰略勝 | RAVE stays in code for tests/`--bench` / RAVE 程式保留 |
| D9 | 2026-08 | Desktop deps merged into `requirements.txt`; `requirements-qt.txt` deleted / 桌面依賴併入單一 requirements 檔 | One install command for everything / 安裝指令只剩一個 | None / 無 |
| D10 | 2026-08 | `MINDMAP.txt` and `docs/` notes stay local / gitignored / 個人筆記不進 repo | Personal working notes are not repository content / 個人工作筆記不屬於 repo 內容 | Not shared via git / 不隨 repo 分享 |
| D11 | 2026-08 | All engine switches/params centralized in `sba.toml`（`$SBA_CONFIG` overrides） / 引擎開關與參數集中到 `sba.toml` | Tune optimizations without touching code; self-tests reset to defaults / 免改碼即可調參，自測重置為預設 | Config must be loaded at import / 設定在 import 時載入 |
| D12 | 2026-08 | Adopted optimizations: opening book, micro tablebase, heuristic rollout, tree reuse, dynamic UCT, PW, early stop, fork eval, dynamic depth, killers/LMR/aspiration, symmetry, node pool, bitboard, parallel MCTS / 採用優化清單 | Bench favors MCTS with heuristic rollout + dynamic UCT + reuse (60% vs RAVE/GRAVE at 300 sims); bitboard measured no gain with the rollout, kept off / bench 顯示優化後純 MCTS 最強（60%）；bitboard 實測無增益故預設關 | More switches to tune; bitboard code kept but off / 開關變多；bitboard 保留但預設關 |
| D13 | 2026-08 | AlphaZero MCTS uses leaf-parallel batched inference (`BATCH_SIZE=16`, `VIRTUAL_LOSS=2`) / AlphaZero MCTS 改為 leaf-parallel batch 推論 | Batching cuts per-iteration kernel launches: ~3.2x on GPU and ~7.8x on CPU in the 20-game bench, quality unchanged (8-0 vs random; move noise within baseline) / batch 大幅降低 kernel launch 開銷，品質不變 | Search switched to standard AZ full expansion (evaluates the leaf itself); low-branching positions re-evaluate duplicates / 改為標準 AZ 全展開語意，低分支局面會重複評估 |
| D14 | 2026-08 | Added `Flat MCTS` (hidden from menus, research only) / 新增 Flat MCTS（選單隱藏，僅供研究） | A one-ply baseline that scores each move with independent root-level playouts — useful for learning how tree search (MCTS) beats flat sampling / 單層基準：每個走法各自做 root 層 rollout，用來對照樹搜尋的價值 | Another engine to maintain for tests and `--bench` / 多一個需維護的測試/bench 引擎 |
| D15 | 2026-08 | Win-rate chart reuses the assistant's search (`analyze_position`) / 勝率折線圖改吃 AI 助手的搜尋結果 | The assistant already runs a full-budget MCTS on the same position; the old separate ≤250-sim search per move was redundant and weaker. Now one search yields both top moves and (X, draw, O) rates / 助手已對同一局面做全預算搜尋，另跑 ≤250 次的搜尋既重複又較弱；改為單一搜尋同時產出最佳步與三方勝率 | Ultimate history points fill asynchronously (None placeholders until the search finishes) / 終極模式歷史點改為非同步填入（未完成前為 None） |
| D16 | 2026-08 | Async AI moves are dropped when the position changed (Qt `gen` guard, web `g0` snapshot + `nonlocal game` rebind) / 非同步 AI 步在局面變更時丟棄 | Rewinding or restarting while an engine was thinking corrupted the board; dropping stale results keeps Qt/Web state consistent / 回退或重開時引擎還在思考會弄髒棋盤，丟棄過期結果維持狀態一致 | A move computed just before a rewind is discarded / 回退前一刻算好的步會被丟棄 |
| D17 | 2026-08 | AlphaZero MCTS uses a fixed 256-wide padded batch and forces `model.eval()` / AlphaZero MCTS 固定 256 寬 padding batch 並強制 eval 模式 | One tensor shape per process = one MIOpen kernel lookup (stability on Windows); BatchNorm in train mode computed degenerate batch stats on duplicated padded states / 單一 shape 讓 MIOpen 只查一次 kernel；train mode 的 BatchNorm 對重複 padding 會算出退化統計 | Low-branching positions waste up to ~55% of the batch on discarded padding / 低分支局面最多約 55% 的 batch 花在丟棄的 padding 上 |
| D18 | 2026-08 | AlphaZero training: multi-process self-play (`--workers`), heuristic win/block rollouts, Dirichlet root noise, LR/temp annealing, mid-run checkpoints / AlphaZero 訓練：多進程自對弈、啟發式 rollout、Dirichlet 噪聲、LR/temp 退火、中途 checkpoint | Standard AZ exploration ingredients plus ~3x throughput at 8 workers; threaded shared-inference measured GIL-bound and slower / 標準 AZ 探索元件；8 worker 約 3 倍吞吐，thread 共享推論實測受 GIL 限制較慢 | Workers play with weights up to 2×workers games stale; replay needs a bigger cap to absorb it / worker 權重最多滯後 2×workers 局，replay 需加大以吸收 |
| D19 | 2026-08 | Minimax Pro root move ordering uses `eval_ultimate` (root only, `use_eval_ordering` switch) / Minimax Pro 根節點改用 `eval_ultimate` 排序（僅根節點，`use_eval_ordering` 開關） | A 20-game A/B found Pro at only 32.5% vs plain Minimax (depth 4); aspiration/killers/TT/depth-bias had zero effect, but root ordering by `eval_ultimate` restored parity (~45%), and Pro vs MCTS improved 40% → 47.5% / 20 局 A/B 發現 Pro 對普通 Minimax 僅 32.5%；aspiration/killers/TT/深度偏置皆無影響，根節點改用 eval_ultimate 排序後恢復持平（~45%），對 MCTS 由 40% 升至 47.5% | Interior nodes keep the cheap heuristic ordering; one more config switch / 內層節點維持便宜排序；多一個設定開關 |
| D20 | 2026-08 | MCTS stays the default Ultimate engine; Minimax (depth 4) only wins at low budgets / 終極模式預設維持 MCTS；Minimax（深度 4）只在低預算勝出 | 30-game benches: Minimax vs MCTS@800 = 63.3% (Minimax wins), vs MCTS@2000 = 40.0% (MCTS wins) — crossover around 1200–1600 sims; MCTS has no depth cap and scales with compute, Minimax is capped and needs the handcrafted eval / 30 局實測：Minimax 對 MCTS@800 = 63.3%、對 MCTS@2000 = 40.0%，交叉點約 1200–1600 sims；MCTS 無深度上限、隨預算縮放，Minimax 封頂且依賴手工評估 | MCTS needs enough budget (default 1600); fixed-depth Minimax is better for low-latency play / MCTS 需要足夠預算（預設 1600）；固定深度 Minimax 在低延遲場景較好 |

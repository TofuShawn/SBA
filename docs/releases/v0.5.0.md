# SBA v0.5.0

The removal release: the pure-Python search stack and the pure-Python
Ultimate rules retire — the native C engine IS the search backend and the
Rust state layer IS the rules implementation. The python tree stays
archived on `archive/python-reference`; the training/self-play layer
(still Python + torch) runs over the Rust state layer and remains the
campaign channel. Breaking by design; details per decision:
`docs/decisions.md` (D62–D65).

## Removal (D65)

- `engines/mcts.py` (709 lines: UCT / RAVE / GRAVE trees + the python
  tree-reuse cache) and `engines/minimax.py` (291 lines: alpha-beta and
  Minimax Pro) are deleted, with alphazero's heuristic-rollout blend —
  the pure-network recipe (D58) is the only recipe. `core/game.py` drops
  `UltimateGame` and `BitUltimateGame`; `NormalGame` stays.
- The Rust state layer is the ultimate rules implementation
  (`az.rustbridge.RustUltimateGame`); the cdylib is a hard prerequisite
  and ships in the Windows package. `encode()` fills the whole ultimate
  tensor in one FFI call.
- `ai.py` slims to the dispatch it always was: every search type routes
  to the C engine and raises a clear RuntimeError without it — no
  DLL-less search contract anymore. AlphaZero requires torch plus a
  trained model.
- **Capability matrix**: the MCTS family has no Normal backend (the C
  kernels serialize Ultimate layouts only). The engine menus follow it
  upstream (TUI / QtUI / bench), `bench` rejects MCTS-family engines on
  Normal, and Normal's Minimax / Minimax Pro route to the C perfect
  solver.
- `bench_rust` retires (its A/B premise was the python reference);
  `config.toml` keys `engine.rust_game` / `engine.bitboard` /
  `engine.object_pool` / `engine.reuse_cache` die with their python-only
  consumers (`tree_reuse` / `workers` / `multithreaded` / `uct_c` /
  `rave_k` stay — the C backends consume them).

## Correctness anchors

- **Encode goldens frozen** (`tests/golden/encode_golden.*`): 40 seeded
  model-free positions — terminal rows included — frozen from the
  pure-Python encode with the Rust state layer agreeing BITWISE at freeze
  time (the terminal turn-flip contract is now proven; the random dumps
  never covered it). The anchor runs torch-free and survives this
  release's own retirement.
- The wave-search goldens keep the search anchor; the rust-vs-python
  parity fuzz retires with its reference. The rust-vs-python state-layer
  parity fuzz is re-anchored as rust-only contract pins (error texts,
  `apply_move` routing, FFI fast paths, handle hygiene).
- **Pipeline equivalence proven**: a post-removal standard campaign (400
  games, sims 80, pure-net, seed 20261128) trains in 388 s and its model
  splits 10 - 0 - 10 against the pre-removal same-recipe model at equal
  budget — the removal did not degrade training output. Against plain
  MCTS@800 it scores 0-1/20, the documented reference behavior (README).

## Backend closure (D64) + upstream

- `cubecl-linalg` 0.4/0.5 `tiling2d` silently corrupts f32 matmul when
  `K%32≠0 ∧ N%64==0` — root cause: `vertical_block_check` bounds K reads
  against the wrong dimension. Filed upstream with a standalone repro and
  the verified one-line fix: tracel-ai/cubecl#2339. The burn kernel
  ceiling stays ~720 GFLOP/s SIMT (~1% of hardware peak) and DX12 is not
  a path — "backend first, then delete Python" has no evidenced path,
  hence this release's shape.

## Tooling / CI

- Suite 211 → 184 python tests (the rust contract pins replace the parity
  fuzz; the python-engine tests retire with their subjects); the coverage
  floor holds at 65% (65.08%); mypy on the FFI boundary and the blocking
  pip-audit gate unchanged; `dev.py` drops the bench-rust task.
- The engine menus are driven by `session.SBA.ai_options_for()` — one
  source of truth for the capability matrix across TUI, QtUI and bench.

## Packaging

- Requires Python 3.12; torch stays optional (training only). Both native
  DLLs (`sba_engine.dll`, `sba_game.dll`) ship in the Windows package —
  no compiler needed on the user machine.
- Breaking: scripts calling the removed python engines, `UltimateGame`,
  or the deleted config keys should move to the C engine path or the Rust
  state layer — `archive/python-reference` preserves the retired source.

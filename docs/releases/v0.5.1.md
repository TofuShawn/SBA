# SBA v0.5.1

A config-surface fix: v0.5.0 removed the pure-Python engines but the
configuration world still described them. No behavior change — every
removed key had zero consumers since v0.5.0.

## Fixed

- **Orphan config keys dropped** from the defaults (`progressive_widening`,
  `early_stop`, `reuse_cache`): their only readers were the python engines
  that v0.5.0 retired. Unknown keys left in an existing `config.toml`
  remain harmless — configuration loads by key with code defaults for
  anything missing.
- **The QtUI Settings page tells the truth**: the deleted keys
  (`bitboard`, `object_pool`) are no longer listed, the multithreaded
  switch reads "C root parallelization" (not "C tree / Python fallback"),
  and the deck hints no longer promise a python fallback that does not
  exist ("關閉後自動回退純 Python" → 關閉即停用).
- **The tracked `config.toml` cleaned**: the five dead keys removed and
  the D-era comment clauses updated (symmetry / micro_tablebase /
  c_rollout_pattern now name the C backend only).

## Compatibility

- No behavior change: engine selection, the capability matrix (D65), and
  every search/training path are exactly v0.5.0.
- Existing `config.toml` files need no edits; leftover unknown keys are
  ignored by the loader.

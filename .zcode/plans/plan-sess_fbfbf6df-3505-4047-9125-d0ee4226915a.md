## A. ai.py

**#2 log 未定义**：模块顶部补 `import logging` 与 `log = logging.getLogger('ai')`（与 SBA.py 同款），AlphaZero 无模型回退不再 NameError。

**#6 负探索常数**：`mcts_search` / `mcts_rave_search` / `mcts_grave_search` 在建立 root 后记录 `start_visits = root.visits`，三处 `_uct_scale(c, root.visits, iterations)` 改为传 `root.visits - start_visits`（只计本次搜索的访问量）。复用后缩放系数始终落在 [0.6c, c]，不再变负。early_stop 不动（默认关闭，复用下自然退化不触发）。

**#7 跨回应树复用（完整修复）**：
- 新增 `_REUSE_LAST = {}`（ai_type → 上次落子后的子树根节点）。
- 新增 helper `_diff_move(old_state, new_game)`：Normal 对比 `board`、Ultimate 对比 `micro`（经 `.micro` duck-typing 同时支持 list 版与 BitUltimateGame），恰好一个新增格才返回该步，否则 None（回退/分支/换局自动退化全新搜索）。
- `_mcts_move` 查找顺序：先 `_REUSE.pop(key)`（保留同引擎连续命中路径）；miss 时取 `_REUSE_LAST[ai_type]`，用 `_diff_move(last.state, game)` 得出对手回应 r，再 `next((c for c in last.children if c.move == r), None)` 下钻得到当前局面的子树（diff==1 保证子节点 state 即当前局面）。
- 存树时同步更新 `_REUSE_LAST[ai_type] = child`；`reset_engine_caches()` 一并清空。GIL 下 dict 操作原子、误命中由位置一致性保证。

**#12 bitboard×多线程**：`mcts_move_parallel` 开头做一次 `BitUltimateGame.from_game(game)`（cfg bitboard 且 UltimateGame 时），各线程用 `mcts_search(base.clone(), chunk)`。sba.toml 默认保持 `multithreaded=true`（已确认）。

**#13 终局深度计分**：`_minimax_ultimate` 终局返回 `100000 - depth if result == ai_player else depth - 100000`（更近的胜利/更远的失败优先，与 `_minimax_normal` 对齐）。

**#14 aspiration 窗口**：`margin = max(200, int(abs(prev_val) * 0.1))`，`alpha, beta = prev_val - margin, prev_val + margin`（匹配 ±1000+ 的评估量级，大幅减少全窗重搜）。

**#15 空 stats 边界**：`mcts_move_parallel` 空 stats 分支改为 `moves = game.legal_moves(); return random.choice(moves) if moves else None`。

**#20 _TT_MAX 动态化**：删模块级 `_TT_MAX = cfg_engine(...)`，新增 `_tt_max()` 动态读取，`_negamax_tt` 存表判断改用 `len(_get_tt()) < _tt_max()`，`set_engine_config` 改 `tt_max` 即时生效。

**#21 分析走 bitboard**：`analyze_position` 与 `position_win_rates` 的 Ultimate 分支在 `cfg_engine('bitboard')` 时改用 `BitUltimateGame.from_game(game)` 搜索；顶部 import 加入 `BitUltimateGame` 并删除 `_mcts_move` 内的局部导入。

## B. alphazero.py

**#16 eval_every 生效**：训练进度行条件改为 `it % max(1, eval_every) == 0 or it == games`（CLI 已传参，仅函数体内未使用）。

**#17 select_move 除零防御**：temp>0 分支加 `s = p.sum(); if s <= 0: return random.choice(moves); p /= s`（当前路径到不了全零，纯防御）。

## C. game.py

**#25 BitUltimateGame 接口对齐**：`make_move` 开头加占用检查 `if (self.x | self.o) & bit: raise ValueError('cell is occupied')`（注意括号）；`macro` property 对「满而平」的宏返回 `'D'`（`self._micro_bits(m) == 0x1FF` 时），与 `UltimateGame` 一致。

## D. qtui.py

**#4 AI 落子世代守卫**：`run_ai` 里快照 `gen = self.gen`，`worker.move_ready.connect(lambda move, g=gen: self.on_ai_done(move, g))`；`on_ai_done(self, move, gen)` 开头 `if gen != self.gen: return`（丢过期棋）。`on_ai_failed` 同样加 gen 守卫（防止过期失败误清新游戏/新局面的 busy 标志）。

**#5 PVC 回退死锁**：`go_to_step` 中 `s['cvc_paused'] = s['mode'] == 'cvc' and k < len(moves)`（PVC 不再残留暂停位）；末尾分支改为：cvc 未暂停且 AI 回合 → `cvc_timer.start()`；elif `mode == 'pvc'` 且未结束且 AI 回合 → `pvc_timer.start(300)`。

**#9 历史回填防串位**：`on_analysis_done` 回填 `history[step]` 的条件加 `gen == self.gen`（回退分支后旧分析结果不再写进新分支的槽位）。

## E. webui.py

**#1 闭包失效**：`go_to_step` 首行加 `nonlocal game`，`session['game'] = g` 后同步 `game = g`。同时硬化过期 AI 任务：`step_ai_move` 把发起时的游戏对象传入 `finish_ai_move(..., g0=game)`；`finish_ai_move` 用 `g0` 做搜索，apply 前检查 `g0 is session['game']`，`ai_busy` 清理判断改用 `id(g0)`（避免 `nonlocal` 重绑后旧任务误清新任务的 busy）。

**#5 Web 版 PVC 死锁**：`go_to_step` 仅在 cvc 模式停 `game_timer`；`cvc_paused` 只在 cvc 置位；末尾：cvc（未暂停且 AI 回合）→ `game_timer.start()`；elif `mode == 'pvc'` 且未结束 → 无条件 `game_timer.start()`（它是 Web 里 PVC 的 AI 驱动器，人类回合 ai_loop 自会跳过）。

**#8 分析异常保护**：`start_analysis` 的 `await asyncio.to_thread(...)` 包 try/except（异常 → `log.error` + `([], (0.5, 0.0, 0.5))` 兜底，与 Qt 一致）；用 try/finally 保证 `session['analyzing'] = False` 一定复位（含 game 已换对象的提前 return 路径），助手不再永久卡死。

**#9 Web 版回填防串位**：`start_analysis` 回填 `history[step]` 条件加 `gen == session['analysis_gen']`。

**#19 控件刷新**：`on_cell_click` 末尾加 `update_cvc_controls()`（与 `apply_ai_move` 对齐，Revert/下一步使能状态即时更新）。
